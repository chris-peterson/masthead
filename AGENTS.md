# masthead

A Claude Code plugin that bootstraps a documentation hub for a repo and keeps it
current. The docs engine (e.g. docsify) sits behind an adapter, so the
operations a hub needs stay the same whichever engine renders it. Its pages are
written for the human who comes next: how the thing works, and what to watch
out for.

## Layout

```text
plugin.yml           the plugin's descriptor; plugin.json is generated from it
skills/bootstrap/    /masthead:bootstrap: SKILL.md is the engine-neutral flow;
                     scripts/<engine>/, assets/<engine>/, and
                     references/<engine>*.md are one engine's adapter
scripts/announce.sh  prints masthead's interop announcements (content.routed)
tests/               unit tests for the scripts (`just test`)
docs/                masthead's own docs site; hand-written pages are tracked,
                     the rest is rendered by `just docs`
.github/workflows/   shipyard's project, docs deploy, and release workflows
```

## Working on it

`just` lists the recipes. `just try` opens a session with this checkout loaded
as a plugin; `just validate` checks it the way CI does.

## Conventions

- This is a public repo: no internal hosts, private paths, or company names in
  committed files.
- `plugin.yml` is the source of record for metadata. `.claude-plugin/plugin.json`
  and `plugin.yml`'s `suite.describe` block are generated by shipyard's project
  job; don't edit them by hand.
- Every command is namespaced `masthead:<skill>`.
- Documentation has three audiences: end users, maintainers, and agents
  (`docs/audiences.md`). masthead owns the end-user hub. cleat routes among all
  three, and shipyard renders the docs site for plugin repos (`shipyard
  build-docs`): a change here shouldn't duplicate what either already does.
